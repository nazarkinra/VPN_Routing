# VPN routing для Android

Android-версия модуля `routing` из проекта для Raspberry Pi: VLESS-туннель со сплит-маршрутизацией.
Российские сайты, банки, Госуслуги, VK, Яндекс и локальная сеть идут напрямую, остальное идёт через VPS.
`bmstu.ru` идёт через корпоративный OpenVPN МГТУ.

## Как это устроено

```
Приложения телефона ──> VpnService (TUN) ──> Xray-core (tun inbound + sniffing)
                                               ├── bmstu.ru (TCP) ──> SOCKS 127.0.0.1 ──> OpenVPN МГТУ (или напрямую, пока туннель опущен)
                                               ├── .ru/.su/.рф, банки, исключения, LAN ──> напрямую
                                               ├── DNS (порт 53) ──> DNS-модуль Xray
                                               │      ├── российские домены ──> DNS текущей сети / 77.88.8.8
                                               │      └── остальные ──> 8.8.8.8 по TCP через VPN
                                               ├── QUIC (UDP/443) за рубеж ──> отклоняется (переход на TCP)
                                               └── всё остальное ──> VLESS ──> VPS
```

На Pi работали два ядра: sing-box принимал трафик, Xray отправлял его на VPS. На телефоне их заменяет одно ядро
Xray ([AndroidLibXrayLite](https://github.com/2dust/AndroidLibXrayLite) v26.10.31).
Правила те же, что в `sing-box.json.template`. Они собраны в `RoutingRules.java`.

| Raspberry Pi | Android |
|---|---|
| `update-vpn "vless://…"` | поле «VPN-ключ», кнопка «Применить». Если с новым ключом ядро не запустилось, работает прежний |
| `add-exception example.com` / `--remove` | раздел «Сайты напрямую»: домен, адрес сайта, кириллический домен, IP или подсеть |
| `check-vpn` | кнопка «Проверить»: задержка до сервера через VPN |
| IP сервера в direct-исключениях, `sockopt.interface` | приложение исключено из своего же VPN (`addDisallowedApplication`) |
| DNS домашнего роутера для `.ru` | DNS текущей сети (Wi-Fi или оператор). При смене сети ядро перезапускается |
| служба `bmstu-vpn`, интерфейс `bmstu0` | клиент OpenVPN внутри приложения, раздел «VPN МГТУ» |
| `openvpn/bmstu.auth` | логин и пароль в разделе «VPN МГТУ» (хранятся только на телефоне) |
| загрузка `.ovpn` в панели, откат за 30 с | «Загрузить .ovpn»: если туннель с новым файлом не поднялся, возвращается прежний |
| systemd, автозапуск | системная настройка «Постоянная VPN» |

Поддерживаются транспорты `tcp`, `raw`, `ws`, `grpc`, `httpupgrade`, `xhttp` и защита `none`, `tls`, `reality`.

## VPN МГТУ

На Android одновременно работает только один VPN, поэтому протокол OpenVPN выполняется в памяти приложения:
клиент [minivpn](https://github.com/ooni/minivpn) и стек TCP/IP gVisor поверх туннеля (`golib/bmstuvpn`).
Xray направляет `bmstu.ru` в локальный SOCKS5-прокси со случайным логином и паролем. Прокси работает,
пока включён VPN: при поднятом туннеле ведёт соединения через него, иначе напрямую.
Поэтому `bmstu.ru` доступен всегда, как на Pi, и подъём или падение туннеля не перезапускает Xray.

- Файл профиля `.ovpn` в приложение не встроен (репозиторий публичный): его импортируют кнопкой «Импорт»
  на вкладке МГТУ. Пока файла нет, туннель не запускается, вкладка подсказывает, что делать.
  Из файла берутся только настройки из белого списка, как в `bmstu-config.py`.
- Если сервер отклонил логин или пароль, повтор будет через 5 минут, чтобы учётную запись не заблокировали.
  При других ошибках повтор через 30 с, затем интервал удваивается до 5 минут.
- Туннель держится пингами OpenVPN каждые 10 с. Раз в минуту проверяется соединение с `bmstu.ru:443`
  через туннель. После трёх неудач подряд туннель переподключается.
  Это же срабатывает при смене ключей сервером (`reneg-sec`), которую minivpn не поддерживает.
- При смене сети (Wi-Fi ↔ мобильная) туннель переподключается.
- Маршрутизируются только сайты (TCP): домен определяется по HTTP и TLS, как на Pi.

**Сервер МГТУ допускает одну сессию на учётную запись.** Пока с этой учётной записью подключены Pi
(служба `bmstu-vpn`) или OpenVPN на телефоне, приложение получает `AUTH_FAILED`. Поэтому:

- при отключении клиент отправляет серверу OCC EXIT, и сервер сразу освобождает сессию;
- если приложение было выгружено системой (уведомление не ушло), сервер держит сессию около минуты.
  Первый отказ подряд повторяется через 90 с, следующие — раз в 5 минут, как на Pi;
- после падения туннеля повтор через 30 с.

Сервер — OpenVPN 2.6. Копия minivpn в `golib/third_party/minivpn` исправлена: причина `AUTH_FAILED`
сохраняется, отказ завершает подключение сразу, клиент объявляет шифр (`IV_NCP`, `IV_CIPHERS`).
QUIC к bmstu.ru отклоняется: прокси туннеля работает только по TCP, браузер переходит на TCP.

Ограничения minivpn: нет согласования шифра (NCP), поэтому шифр выбирается заранее. Берётся первый
поддерживаемый из `data-ciphers`, затем `cipher`, иначе AES-256-GCM. Сервер OpenVPN 2.5+ его принимает.
Не поддерживаются `tls-auth`, `tls-crypt` и сжатие, кроме `compress stub` и `comp-lzo no`.

## Сборка

Проект рассчитан на Android Studio Chipmunk (AGP 7.2.1, Gradle 7.3.3, compileSdk 32), minSdk 24.

```
set JAVA_HOME=C:\Program Files\Android\Android Studio\jre
gradlew assembleDebug testDebugUnitTest
```

- В корневом `build.gradle` подключён R8/D8 8.5: встроенный в AGP 7.2 D8 падает на классах gomobile.
- Базы `geoip.dat` и `geosite.dat` из ядра (~27 МБ) в APK не попадают: правила не используют geo-базы.
- Тест `XrayConfigTest` сохраняет примеры конфига в `app/build/xray-configs/`. Их можно проверить командой
  `xray run -test -config app/build/xray-configs/reality.json`.

### Проверка в Nox

Nox (Android 7.1, x86) держит свой adb-сервер старой версии, поэтому команды идут через его `nox_adb`:

```
"D:\Program Files\Nox\bin\nox_adb.exe" connect 127.0.0.1:62001
"D:\Program Files\Nox\bin\nox_adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
```

Отладочная сборка дополнительно содержит ядро под x86: ARM-версия Go-ядра под трансляцией
(libhoudini) в Nox падает. В выпуск x86 не входит. Отладочная сборка также разрешает HTTP к `localhost`,
чтобы проверять подписку с компьютера через `nox_adb reverse tcp:8765 tcp:8765`.

### Библиотека `app/libs/libvpn.aar`

Ядро Xray и клиент МГТУ собраны в одну библиотеку: две gomobile-библиотеки в одном приложении конфликтуют.
Пересобирать её нужно только при изменениях в `golib/` или обновлении Xray:

```
powershell -ExecutionPolicy Bypass -File golib\build.ps1
```

Нужны Go 1.27+ (`F:\Android\go`), gomobile (`go install golang.org/x/mobile/cmd/gomobile@<версия из golib/go.mod>`),
Android NDK (`F:\Android\SDK\ndk\30.0.16248370`) и JDK из Android Studio. Версия Xray задаётся
`github.com/2dust/AndroidLibXrayLite` в `golib/go.mod`.

## Интерфейс

Три вкладки внизу экрана:

- **VPN.** Кнопка подключения с таймером и пингом, текущий сервер, список серверов. «Добавить» принимает
  ссылку `vless://`, несколько ссылок сразу или адрес подписки `https://…`. Подписка разбирается целиком:
  base64 или открытый список, название (`profile-title`), трафик и срок (`subscription-userinfo`),
  интервал обновления и объявление провайдера. Устаревшие подписки обновляются при открытии приложения.
  Пинг меряет реальный запрос через каждый сервер. Сервер можно сменить на ходу: если новый не запустится,
  останется прежний.
- **МГТУ.** Профиль с переключателем, состояние, статистика туннеля (время, адрес, трафик и скорость),
  учётные данные, файл профиля (импорт и откат) и журнал подключения.
- **Напрямую.** Что идёт без VPN: ваши сайты (добавление и удаление), `bmstu.ru`, доменные зоны,
  сайты и сервисы, сети и протоколы. Есть поиск. Встроенные зоны, сайты и сервисы тоже можно удалить,
  а вернуть все разом — в меню «Вернуть встроенные». Локальная сеть, служебные адреса и порты VPN
  закреплены: без них перестанут работать устройства в сети и туннель МГТУ.

Поддерживаются серверы VLESS и Hysteria2 (`hysteria2://`, `hy2://`). Ссылки других протоколов
из подписки пропускаются, их число видно в заголовке подписки.

- **VLESS:** транспорты `tcp`, `raw`, `ws`, `grpc`, `httpupgrade`, `xhttp` (с `extra`), защита `none`, `tls`
  (`alpn`, `vcn`, `pcs`), `reality`; `encryption`, `fm` (finalmask: фрагментация TLS и т. п.).
  Mux включается только без `flow` и не для XHTTP: у XHTTP своё мультиплексирование.
- **Hysteria2:** выход Xray `hysteria` версии 2, ALPN `h3`, `sni`, `obfs=salamander`, `pinSHA256`, `fm`.
  Не поддерживаются смена портов (port hopping) и `insecure=1`: в этой версии Xray `allowInsecure` удалён,
  вместо него — закрепление сертификата по отпечатку (`pinSHA256`).
- Подписка запрашивается с User-Agent `v2rayN/7.0 (VPNrouting)`: панели выбирают формат по User-Agent и на
  незнакомый отвечают 404, а для v2rayN отдают список ссылок.

## Обновления

Приложение само проверяет новую версию в репозитории: при запуске (не чаще раза в 12 часов) и по пункту
меню «Проверить обновления». Источник — `version.json` в корне репозитория, APK — `VPN_routing.apk` там же.
При обновлении приложение скачивает APK, сверяет размер и SHA-256 и открывает системную установку
(при первом обновлении Android попросит разрешить установку из этого приложения). Настройки сохраняются.

Как выпустить версию:

1. Увеличить `versionCode` и `versionName` в `app/build.gradle`.
2. Собрать и выложить:
   ```
   powershell -ExecutionPolicy Bypass -File android\publish_apk.ps1 -Notes "Что нового"
   ```
   Скрипт собирает подписанный APK, прогоняет тесты, кладёт в корень `VPN_routing.apk` и `version.json`
   и не даст опубликовать версию с тем же или меньшим `versionCode`.
3. `git add VPN_routing.apk version.json android`, коммит, пуш.

Проверка работает, только пока репозиторий публичный: из приватного файлы без входа не скачать.
Для проверки на эмуляторе адрес подменяется: `gradlew assembleDebug -PupdateBase=http://localhost:8765/`
(и `adb reverse tcp:8765 tcp:8765`).

## Быстрые команды

Долгое нажатие на иконку приложения (Android 7.1+) показывает ярлыки **«Включить VPN»** и
**«Выключить VPN»**. Их можно вынести на рабочий стол или выбрать в сценарии, если приложение сценариев
умеет запускать ярлыки приложений.

Для приложений, которые отправляют интент (MacroDroid, Tasker, Automate и т. п.), есть три действия.
Это запуск активити `com.example.vpn_routing/.CommandActivity` (окна у неё нет):

| Действие (action) | Что делает |
|---|---|
| `com.example.vpn_routing.action.CONNECT` | включить VPN (вместе с туннелем МГТУ, если он включён) |
| `com.example.vpn_routing.action.DISCONNECT` | выключить VPN |
| `com.example.vpn_routing.action.TOGGLE` | переключить |

Пример для проверки с компьютера:

```
adb shell am start -a com.example.vpn_routing.action.CONNECT
```

Если система ещё не выдала приложению разрешение на VPN, команда «включить» откроет приложение
и покажет системный запрос. После этого команды работают без окна.

## Файлы

- `MainActivity.java`, `VpnFragment.java`, `CorpFragment.java`, `DirectFragment.java`: экран и вкладки.
- `ServerStore.java`, `SubscriptionFetcher.java`, `Pinger.java`, `ServerAdapter.java`: серверы, подписки, пинг.
- `DirectAdapter.java`, `GroupBackground.java`, `Format.java`: списки и форматирование.
- `RoutingVpnService.java`: VPN-служба, запуск ядра, откат ключа, слежение за сетью, уведомление.
- `XrayConfig.java`: сборка конфига Xray (аналог `update_xray` и шаблона sing-box).
- `BmstuManager.java`: туннель МГТУ, повторы, откат `.ovpn` (аналог `bmstu-vpn` и `bmstu-vpn-hook.sh`).
- `BmstuConfig.java`: проверка и очистка `.ovpn` (аналог `bmstu-config.py`).
- `VlessLink.java`: разбор ссылки `vless://` (аналог `parse_vless`).
- `Exceptions.java`, `Settings.java`: нормализация и хранение исключений, ключа и настроек МГТУ.
- `RoutingRules.java`: встроенные домены, сети и порты для прямого выхода.
- `MainActivity.java`: экран приложения.
- `golib/bmstuvpn`: клиент OpenVPN (minivpn + gVisor netstack) и SOCKS5-прокси на Go.
