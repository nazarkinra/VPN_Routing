# VPN routing для Windows и Linux

ПК-версия Android-приложения из [`../android`](../android/): то же ядро Xray, те же правила маршрутизации,
тот же клиент OpenVPN МГТУ. Обычное приложение со своим окном (Fyne) — разделы VPN, МГТУ, Напрямую и Настройки,
без браузера.

```
Программы компьютера ──> TUN (Wintun / /dev/net/tun) ──> Xray-core (tun inbound + sniffing)
                                                           ├── bmstu.ru (TCP) ──> SOCKS 127.0.0.1 ──> OpenVPN МГТУ (или напрямую)
                                                           ├── .ru/.su/.рф, банки, исключения, LAN ──> напрямую
                                                           ├── DNS (порт 53) ──> DNS-модуль Xray
                                                           │      ├── российские домены ──> DNS текущей сети / 77.88.8.8
                                                           │      └── остальные ──> 8.8.8.8 по TCP через VPN
                                                           ├── QUIC (UDP/443) за рубеж ──> отклоняется
                                                           └── всё остальное ──> VLESS / Hysteria2 ──> VPS
```

## Установка

**Windows 10/11 (x64).** Скачайте **[VPN_routing-setup.exe](../VPN_routing-setup.exe)** и запустите. Установщик
спросит права администратора, поставит программу в `C:\Program Files\VPN routing` и создаст ярлыки
«VPN routing» в меню «Пуск» и на рабочем столе. Удаление — «Параметры → Приложения → VPN routing → Удалить»
(спросит, удалять ли настройки). Тихая установка: `VPN_routing-setup.exe /S`.

Как у Happ, VPN работает в службе Windows «VPN routing» (от имени системы, запускается вместе с Windows), а окно —
обычная программа без прав администратора. Права администратора нужны один раз — при установке; ярлык потом
открывает окно без вопросов. В трее — значок с точкой состояния: крестик прячет окно в трей, щелчок по значку
или повторный запуск ярлыка открывают его снова, «Выход» выключает VPN и закрывает окно (служба остаётся
для следующего запуска). Настройки службы — в `C:\ProgramData\VPN routing` (доступ только системе и
администраторам); при установке поверх прежней версии они переносятся из `%APPDATA%\VPN routing`, пароль МГТУ
перешифровывается для службы. «Запускать вместе с Windows» в настройках — служба при загрузке и значок в трее
при входе; «Подключаться при запуске» — VPN сразу после загрузки, как «Постоянная VPN» на Android.
Без установки: архив [VPN_routing-windows.zip](../VPN_routing-windows.zip), `vpnrouting.exe` рядом с `wintun.dll` —
тогда службы нет, VPN и окно работают в одной программе и при запуске спрашивают права администратора.

**Linux (x86-64, systemd, рабочий стол X11 или Wayland).** Скачайте [архив](../VPN_routing-linux-amd64.tar.gz),
распакуйте и установите:

```bash
tar xzf VPN_routing-linux-amd64.tar.gz
```

```bash
sudo ./VPN_routing/install.sh
```

Программа ставится в `/usr/local/bin/vpnrouting`, в меню приложений (раздел «Сеть», поиск «VPN routing»)
появляется ярлык со значком, служба `vpnrouting.service` запускается и включается при загрузке (как
`bmstu-vpn` на Raspberry Pi). VPN работает в службе (от root), а окно — обычная программа пользователя: ярлык
открывает его, крестик закрывает только окно. Окно и команды `vpnrouting connect`, `disconnect`, `status`
обращаются к службе через `/run/vpnrouting/control.sock` без sudo — служба пускает root и пользователя, который
ставил программу. Если служба остановлена, окно предложит запустить её (`systemctl start`, система может
спросить пароль). Добавить ещё пользователя — `sudo vpnrouting install --user ИМЯ`. Удаление —
`sudo ./VPN_routing/uninstall.sh` (`--purge` — вместе с настройками в `/var/lib/vpnrouting`).

Без установки: `sudo ./vpnrouting` (служба) и в другом терминале `./vpnrouting` (окно). Значка в трее на Linux нет.

Собрано в Ubuntu 24.04: нужен glibc 2.38+ (Ubuntu 24.04, Debian 13, Fedora 39, Mint 22 и новее), а также
обычные библиотеки рабочего стола (OpenGL, X11 или Wayland) — они есть в любом дистрибутиве с графической оболочкой.

## Что повторяет из Android-версии

| Android | ПК |
|---|---|
| VpnService + `addDisallowedApplication` | TUN создаёт Xray; его собственные соединения привязаны к физическому интерфейсу (`autoOutboundsInterface`) |
| `VpnService.protect()` для клиента МГТУ | сокеты OpenVPN и прямой выход прокси привязываются к физическому интерфейсу (`IP_UNICAST_IF` / `SO_BINDTODEVICE`) |
| DNS текущей сети из `ConnectivityManager` | DNS интерфейса с маршрутом по умолчанию; при смене сети ядро перезапускается, туннель МГТУ переподключается |
| системный DNS → `172.19.0.2` в туннеле | Windows: DNS адаптера + фильтры WFP против утечек; Linux: `resolvectl` при systemd-resolved |
| уведомление и ярлыки «Включить/Выключить VPN» | значок в трее (Windows) и команды `vpnrouting connect / disconnect / toggle` |
| «Постоянная VPN» | «Запускать при входе» (задача планировщика) / служба systemd + «Подключаться при запуске» |
| SharedPreferences | `settings.json`: `%APPDATA%\VPN routing` на Windows, `/var/lib/vpnrouting` на Linux (права 0600) |
| пароль МГТУ на телефоне | на Windows шифруется DPAPI (расшифровать может только эта учётная запись) |

Всё остальное — как на телефоне: серверы VLESS (`tcp`, `raw`, `ws`, `grpc`, `httpupgrade`, `xhttp`;
`none`, `tls`, `reality`) и Hysteria2, подписки (base64 или список, `profile-title`, `subscription-userinfo`,
интервал, объявление; устаревшие обновляются при запуске и раз в полчаса), пинг серверов, смена сервера на
ходу с откатом, свои сайты напрямую с поиском, туннель МГТУ с повторами (90 с после первого отказа,
затем 5 минут), OCC EXIT при отключении, импорт `.ovpn` с проверкой подключением и откатом.

Как в Android 1.3, на вкладке «Напрямую» можно убрать и встроенные правила (зоны, сайты и сервисы) —
сайты из них пойдут через VPN; кнопка «Вернуть встроенные (N)» возвращает все разом.

## Корпоративные сети (Wi-Fi МГТУ)

То же, что в Android 1.4: обычный DNS (UDP 53) на внешние серверы в таких сетях закрыт, поэтому напрямую
по UDP 53 запросы идут только к DNS, выданному сетью.

- **адрес сервера**: IP из ключа как есть, иначе DNS сети (4 с), затем DoH по IP (`1.1.1.1`, `8.8.8.8`),
  затем DNS по TCP (`8.8.8.8`, `77.88.8.8`); всё — через физическую сеть, мимо туннеля;
- **российские домены и исключения**: DNS сети, затем TCP `77.88.8.8` и DoH `1.1.1.1` напрямую, на каждый
  сервер не больше 2,5 с;
- **остальные домены**: внутри туннеля (TCP `8.8.8.8`, DoH `1.1.1.1`);
- MTU туннеля 1400, локальные сети (`10/8`, `172.16/12`, `192.168/16`) напрямую.

Hysteria2 работает по UDP и в корпоративной сети может не подключиться — нужен сервер VLESS по TCP 443.

**Диагностика.** Если сервер не отвечает, приложение само проверяет TCP-порт и пишет, на каком шаге сбой и
чем получен адрес сервера. Рабочий конфиг ядра со скрытыми UUID, ключами и паролями лежит в папке настроек
(`xray_config.json`), кнопка «Копировать» — в настройках, раздел «Диагностика».

## Обновления

При запуске и затем раз в 12 часов приложение читает `desktop-version.json` из корня репозитория на GitHub.
Если `versionCode` там больше установленного, окно предложит обновиться («Позже» — больше не напоминать об
этой версии; кнопка «Проверить обновления» в настройках проверяет сразу). Архив своей системы скачивается,
сверяются размер и SHA-256, программа заменяется новой и перезапускается; VPN поднимается снова, если был
включён. Настройки сохраняются. Под systemd служба перезапускается сама (`Restart=on-failure`).

## Команды

```
vpnrouting connect      включить VPN (запустит приложение, если оно не запущено)
vpnrouting disconnect   выключить VPN
vpnrouting toggle       переключить
vpnrouting status       состояние
vpnrouting open         открыть окно
vpnrouting quit         выключить VPN и закрыть приложение
```

Окно и команды говорят со службой без сети: на Windows — через именованный канал `\\.\pipe\vpnrouting`
(доступ — система, администраторы и пользователь, который ставил программу; на диске ничего не создаётся), на Linux —
через сокет `/run/vpnrouting/control.sock`. Сетевых портов приложение не открывает.

## Сборка и выпуск

```
powershell -ExecutionPolicy Bypass -File desktop\publish.ps1 -Notes "Что нового"
```

Собирает всё и кладёт в корень репозитория `VPN_routing-setup.exe`, `VPN_routing-windows.zip`, `VPN_routing-linux-amd64.tar.gz`
и `desktop-version.json` (архивы хранятся в Git LFS, как APK). Перед
выпуском увеличьте `VersionCode` и `VersionName` в `buildinfo/buildinfo.go`. Только собрать, без выпуска:

```
powershell -ExecutionPolicy Bypass -File desktop\build.ps1
```

Скрипт прогоняет тесты, собирает `dist\windows\vpnrouting.exe` и `dist\linux-amd64\vpnrouting` в WSL
(`build-wsl.sh`: окну нужен компилятор C), установщик и один раз скачивает `wintun.dll` с https://www.wintun.net
(сверяя контрольную сумму). На Linux без WSL — `desktop/build.sh`.

Что нужно в WSL (Ubuntu 24.04), один раз:

```bash
sudo apt install -y build-essential pkg-config libgl1-mesa-dev xorg-dev libxkbcommon-dev libwayland-dev gcc-mingw-w64-x86-64
```

и Go 1.27+ в `~/.local/go`. Если apt не может скачать пакеты с `archive.ubuntu.com`, переключите источники на
зеркало, например `mirror.yandex.ru`.

- Версия Xray та же, что в Android-версии (`github.com/xtls/xray-core` в `go.mod`).
- `bmstuvpn/` — копия `android/golib/bmstuvpn`, отличается только `protect.go` (привязка сокетов вместо
  `VpnService.protect`). Исправленный minivpn берётся из `android/golib/third_party/minivpn` через `replace`.
- `go test ./...` повторяет тесты Android-версии (ссылки, правила, подписки, `.ovpn`) и проверяет, что
  собранные конфиги принимает само ядро Xray.
- Для проверки окна без прав администратора: `VPNROUTING_NOADMIN=1 VPNROUTING_DATA=<папка> vpnrouting`,
  `VPNROUTING_UI_TAB=0…3` — сразу открыть вкладку (подключение в этом режиме не работает).

## Файлы

- `main.go`, `backend.go`, `launch_*.go`, `platform_*.go` — запуск, права, команды, служба и окно.
- `app/vpn.go` — VPN: запуск ядра, откат ключа, слежение за сетью (аналог `RoutingVpnService.java`).
- `app/bmstu.go` — туннель МГТУ, повторы, откат `.ovpn` (аналог `BmstuManager.java`).
- `app/store.go` — настройки, серверы, подписки, исключения (аналог `Settings.java` и `ServerStore.java`).
- `app/servers.go` — пинг и обновление подписок; `app/xray.go` — запуск ядра и замер задержки.
- `app/update.go` — проверка и установка обновлений (аналог `UpdateManager.java`); `tools/pack` — упаковка выпуска.
- `netenv/resolve.go` — адрес сервера: DNS сети, DoH, DNS по TCP (аналог `ServerResolver.java`).
- `core/dump.go` — копия конфига ядра со скрытыми секретами (аналог `ConfigDump.java`).
- `core/` — разбор ссылок, правила, исключения, конфиг Xray, `.ovpn`, подписки (перенос одноимённых классов).
- `netenv/` — физический интерфейс, его DNS и привязка сокетов.
- `gui/` — окно приложения (Fyne): вкладки, диалоги, значок в трее.
- `api/` — команды и состояние для окна, сокет управления.
- `install/`, `installer/`, `linux/` — установка и удаление (Windows: установщик; Linux: `install.sh`).
- `assets/` — значок, тот же, что у Android-приложения: исходник `icon-source.webp`, из него `go run ./tools/icon`
  делает `vpnrouting.png` 512×512; `tools/res` — ресурсы exe (значок, версия, манифест); `buildinfo/` — номер версии.
